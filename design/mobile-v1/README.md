# Hotlah — approved mobile concept set

The user approved the cream, charcoal, and yellow visual direction, then responded "good" to this first set of four mobile mockups. This approval records the visual concepts; it does not authorize application development or approve the proposed technical stack.

## Screens

1. [Discovery](01-discovery.png): service-first browsing with area, style, and distance controls.
2. [Service and availability](02-service-availability.png): menu details, price, duration, and a multi-day availability grid before submitting a request.
3. [Booking conversation](03-booking-conversation.png): pending approval, cancellation, messaging, and contact/address restrictions.
4. [Merchant dashboard](04-merchant-dashboard.png): subscription-restricted new-request notice, existing appointments, time blocking, and traction metrics.

## Review notes

- Generated using the built-in image-generation tool. The adjacent JSON files preserve the exact original prompts, targeted edit prompts, source paths, and approval context.
- All merchant/customer names, prices, nail photographs, availability, and metrics are example content. Photos are generated, not actual merchant portfolio work.
- These are raster design concepts, not functioning screens. Future implementation must use semantic controls and real text, not a flattened screenshot.
- The selected customer navigation uses dark text/icons and a yellow pill. The availability and conversation images include a targeted correction to align this treatment.
- The merchant dashboard illustrates subscription-restricted access. Its visible confirmed appointments represent previously accessible bookings, not the hidden new request.
- The customer conversation illustrates a pending request. Exact home address and external contact actions remain unavailable before approval.
- Status-bar graphics and example-content labels belong to the mockup presentation. Browser UI and native status bars must be handled by their platform, not copied into the app's content.
- Detailed bilingual layouts, onboarding, region-map interaction, merchant application, unrestricted approval screens, desktop layouts, and edge states remain to be designed. These four screens do not represent completion of all app flows.
- Exact font selection, measured colour tokens, responsive behaviour, touch sizes, and accessibility require validation during detailed design and implementation.
